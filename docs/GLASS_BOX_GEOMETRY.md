# 玻璃盒(screen)几何标定

`renderer.py` 里 `BOX_*` 常数的来源。要改效果先看这里，别瞎调。

## 1. 原片实测

素材 `assets/sample.mp4`（1920×1080, 30fps, 358 帧）。盒子出现在 **192–320 帧**。

盒子把手盖住了，整段 MediaPipe **检测不到任何手**（`detect()` 返回 0 只）。
改用 ROI 切块（左手 `x∈[150,760]`、`y∈[100,900]`，置信度降到 0.15）才在
**帧 312** 抠出左手 21 点，与盒子白描边逐点配准：

| 盒子角 | 屏幕坐标 | 最近手部点 | 距离 |
|---|---|---|---|
| 前上左 | (428, 478) | 中指尖 (401,464) | **31 px** |
| 前下左 | (440, 690) | 小指尖 (413,695) | **27 px** |
| 后下左 | (567, 412)（推导） | 拇指尖 (572,485) | 73 px |
| 后上左 | (555, 200) | —（最近的也差 286 px） | — |

**结论：食指/中指/小指三个指尖压在同一条前棱上（指弧贴着盒子前缘），只有拇指在后侧；
后上角没有任何手指对应，是几何推出来的第四点。**

进深方向：左端 `(127,−278)`、右端 `(−125,−243)`——两端都朝上退、水平相向收敛，
即**一个刚性 3D 长方体的两点透视**，不是两个各自算出来的端面。

其它实测量：

- 指弧展开量（食指尖→小指尖）= 274 px
- 后上棱 / 前上棱 = 1048 / 1297 = **0.81**
- 四角的屏幕「上」分量（相对四角均值）= 前上 −33 / 前下 −245 / 后上 +245 / 后下 +33

## 2. 参数化模型

盒子局部坐标 `(x, u, w)` 右手系：`x` 沿长轴、`u` 沿高、`w` 朝观察者。
前面在 `w=0`（正好落在指弧上），后面在 `w=−D`。

相机俯角和用户 roll **同轴**（都绕长轴），所以合成单一角 `ψ`，不需要翻面状态机：

```
up     = u·cosψ − w·sinψ          屏幕「上」分量
toward = u·sinψ + w·cosψ          朝观察者，越大越近
screen = anchor + (x·â + up·p̂) · f/(f − toward)
```

`â` = 两手锚点连线方向（**含深度分量**，见 §3 的 `BOX_AXIS_Z_GAIN`），
`anchor` = 两手锚点中点。

截面两轴不是 `â` 的 2D 垂线，而是：

```
ĉ₀ = normalize(ẑ − â·â_z)      朝观察者，Gram-Schmidt 正交化 → z 分量恒 ≥0
b̂₀ = ±(ĉ₀ × â)                 屏幕「上」，符号帧间传播（与上帧同向者胜）
```

`ĉ₀` 用 `+ẑ` 正交化而不是叉积，是因为叉积形式的 z 分量正比于 `span_v.x`，
双手 x 差过零时整组基会翻号、盒子瞬间里外翻（实测单帧 608px 跳变）。
`b̂₀` 的符号同理不能按「屏幕上」硬判——那个判据等价于 `span_v.x = 0`，
在长轴竖直时同样 180° 翻转。两处都改成连续化处理（commit `0384397` / `8b7f94c`）。

## 3. 反解出的常数

拿帧 312 的四个角 + 后/前棱比联立数值反解 `(H, D, ψ, f/L)`：

```
盒真高 H = 313.0    进深 D = 461.0    ψ = 0.830 rad (47.6°)    f = 1.10 × L

四角 up   模型 [−32.5, −245.2, +244.6, +33.1]
          实测 [−33,   −245,   +245,   +33  ]     RMS 残差 0.3 px
后/前棱   模型 0.808                实测 0.81
```

落到代码常数：

| 常数 | 值 | 含义 |
|---|---|---|
| `BOX_H_GAIN` | 1.14 | 盒真高 / 指弧展开量（313/274） |
| `BOX_DEPTH_RATIO` | 1.47 | 进深 / 盒真高（461/313） |
| `BOX_ROLL_BIAS` | 0.830 | 静止时的截面转角 rad（= 相机俯角） |
| `BOX_FOCAL` | 1.10 | 弱透视焦距 = 该值 × max(盒长, 高+深) |
| `BOX_ANCHOR_LIFT` | 0.85 | 锚点在 掌心(0) ↔ 指弧中点(1) 之间的位置 |
| `BOX_ROLL_EXPO` | 1.5 | 掌面朝向 → roll 的曲线陡度；**无原片依据，实拍调** |
| `BOX_AXIS_Z_GAIN` | 1.2 | 掌宽比 → 长轴深度分量；**无原片依据，实拍调** |

### 锚点高度（`BOX_ANCHOR_LIFT`）

盒子挂多高由锚点决定。帧 312 左手实测，各候选点距盒子前面中心 (434,584)：

| 候选 | 坐标 | 距离 |
|---|---|---|
| 掌心 `_palm_center` | (354.0, 648.0) | **102.5 px** |
| MCP 中点 | (343.6, 619.3) | 97.0 px |
| `MIDDLE_MCP` | (337.5, 588.5) | 96.6 px |
| 指弧中点 | (408.0, 561.9) | **34.1 px** |

沿「掌心→指弧中点」插值，最优 `t = 0.95`（残差 33.7 px）。
默认取 **0.85**（残差 35.3 px）：几乎恢复原片高度，同时掺 15% 掌心衰减指尖噪声。
纯用掌心会让盒子明显挂在手下方（偏 102 px ≈ 44% 盒高）。

### 长轴的深度分量（`BOX_AXIS_Z_GAIN`）

长轴若锁在像平面内，端面的外法线只有 ±x 分量，相机在 `x=0` 平面上 →
**端面结构上永不可见，盒子只能绕自己滚，指不了别的方向**。

深度分量取自两手掌宽比（投影尺寸 ∝ 1/距离）：

```
dz = BOX_AXIS_Z_GAIN · span · (掌宽R − 掌宽L) / (掌宽R + 掌宽L)
```

实测行为（合成手）：

```
掌宽 左134 右134 → dz    +0 → 可见面 前+顶
掌宽 左240 右95  → dz  -674 → 可见面 前+顶+左端     一只手前伸, 盒子转过来
掌宽 左95  右240 → dz  +674 → 可见面 前+顶+右端
```

`BOX_FOCAL` 用 `max(盒长, 高+深)` 兜底是为了保证 `f − toward` 恒为正，
双手贴近时不会被透视除爆。

## 3.5 旋转的跟手性（ψ 的速度自适应滤波）

固定 EMA（`BOX_SMOOTH=0.6`）快慢一视同仁，实测 0.4s 快速翻手时：

```
t=  0ms  手  -67.0°  盒  -67.0°  落后  0.0°
t=133ms  手  +16.3°  盒  -10.9°  落后 27.2°
t=267ms  手  +99.6°  盒  +68.9°  落后 30.7°     ← 全程恒定落后 ~31°
t=400ms  手 +162.1°  盒 +143.5°  落后 18.7°
手停下后还要 5 帧(167ms)才追上
```

这就是「太滑、不跟手」。直接调小系数会让静止时抖起来，所以改成**转得越快滤波越松**
（与 `tracker.py` 的 landmark 级 One Euro 同源思路，但按「帧」而非墙钟计时，
保证离线渲染可复现）：

```
rate ← rate·BOX_RATE_SMOOTH + |ψ_raw − ψ|·(1−BOX_RATE_SMOOTH)
k    = min(roll_resp + BOX_ROLL_RESP_GAIN·rate, BOX_ROLL_RESP_MAX)
ψ    ← ψ + (ψ_raw − ψ)·k
```

合成信号对比：

| 滤波 | 翻手最大落后 | 末尾误差 | 追上耗时 |
|---|---|---|---|
| 固定 EMA 0.6（旧） | 31.1° | 18.7° | 167 ms |
| 固定 EMA 0.3 | 8.9° | 2.7° | 33 ms |
| **自适应 base 0.40** | **7.4°** | **0.6°** | **0 ms** |

自适应在每一项跟手指标上都赢过固定 EMA 0.3，静止残抖还更小。

用**原片真实 `_orient` 序列**（187 个双手帧）驱动：跟踪 RMS 误差
**14.76° → 2.35°（6.3×）**。

实测 `_orient` 帧间差分是**重尾**分布（中位 |Δ| 0.010，p95 0.265，σ 0.129），
所以试过的死区（floor）对它无效（14.10° → 14.11°，等于没有），**没有采用**。

## 3.6 翻转映射：为什么不是线性 gain

**背红面的投影面积对 ψ 是单峰的，峰在 180°。** 所以「能不能看到背面」和
「背面有多大」是两回事，只看二值可见性会得出反向的结论：

| 线性 gain | ψ 正端 | 背红面积 | ψ 负端 | 背红面积 |
|---|---|---|---|---|
| 2.0 | +162° | **89.6%** | −67° | 0% |
| 3.0 | +219° | 56.4% | −124° | 27.4% |

gain 2.0 的正方向本来就能翻出 89.6% 的红背面；提到 3.0 是为了救负方向，
结果正端越过峰值，把 89.6% 砍成 56.4%。**线性映射只能在一条直线上挑落点，
两端顾此失彼。**

改成两端收敛到 ±180°（正好是峰值）：

```
ψ = BIAS + (π·sign(o) − BIAS) · |o|^BOX_ROLL_EXPO
```

- `o=0` → 恰好 `BIAS`（47.6°），**静止外观逐像素不变**
- `o=±1` → ±180°，背面满屏
- `dψ/do = (π − sign(o)·BIAS)·EXPO·|o|^(EXPO−1) > 0` 恒成立 → 严格单调
- `BOX_ROLL_GAIN` 退役

端到端实测（原片 187 个双手帧，走完整滤波+渲染路径）：

| | 见背 | 背≥50% | 背面均面积 |
|---|---|---|---|
| linear gain 2.0 | 5.9% | 3.7% | 3.6% |
| linear gain 3.0 | 54.5% | 5.3% | 14.3% |
| **expo 1.5** | **42.8%** | **39.6%** | **39.4%** |

「背≥50% 的帧」是真正代表"看得见后面"的指标，提升 **7.5 倍**。

### 验证方法的教训

在此之前所有实验都是**无噪 ψ 扫描 + 只看二值可见性**，从没把
「真实 `_orient` 序列 → 滤波 → 渲染 → 数可见面切换率」串起来跑过。
所以 gain 3.0 把颜色切换从 3.37 次/秒推到 5.29 次/秒（频闪）这件事，
在提交前根本没有机会被看见。端到端验证器已固化为 `tools/e2e_check.py`
（默认跑断言，`--sweep` 扫参数）。

试过给面可见性加**面积滞回**来压切换率，实测无效（6.90 → 7.22 次/秒，
EXPO=2.0 时反而更差）——切换是 ψ 本身在大幅摆动造成的（p95 |Δψ| = 54°），
3% 的面积阈值挡不住这种量级。已删除，不要重复尝试。

## 3.7 角速度限幅：把切换率压回红线内

`BOX_ROLL_MAX_RATE` 从 20 降到 **10**（°/检测帧）。

`tools/e2e_check.py --sweep` 的 expo × cap 网格（样片 154 个双手帧，expo 1.5）：

| cap °/帧 | 切换/s | 见背 | 背≥50% | 顶均 |
|---|---|---|---|---|
| 20（旧） | **6.43** | 43.5% | 33.8% | 23.5% |
| 15 | 5.84 | 43.5% | 32.5% | 27.4% |
| 12 | 5.26 | 47.4% | 33.8% | 27.5% |
| **10（现）** | **4.87** | **54.5%** | **36.4%** | 32.3% |
| 8 | 4.68 | 55.2% | 39.6% | 33.2% |

两个反直觉的结论：

1. **压切换率不用拿可见性去换。** 限幅挡掉的是 `_orient` 饱和区翻符号造成的
   瞬移，ψ 少被甩出去，停留在「看得见背面」区间的时间反而更长——cap 20→10
   切换率降 24%，背≥50% 反而从 33.8% 涨到 36.4%。
2. **cap 是主控，expo 不是。** 同一个 cap 下换 expo（1.5 / 2.0 / 2.5）切换率只
   差 0.2–0.6 次/秒；同一个 expo 下换 cap 能差 1.8 次/秒。expo 决定静止外观和
   中心灵敏度，不该被拿来当降噪旋钮。

cap=8 的数字更好看，**没有采用**：8°/帧 @30fps = 240°/s，已经低于真实快速翻腕
（~300°/s），会削掉真动作。10°/帧 = 300°/s 是「仍在真手速之上」的下界。

切换率 5 次/秒这条线现在是 `tools/e2e_check.py` 的硬断言，越过就退出码非 0。

## 3.8 背红面为什么退役了（实测值保留在此）

§3.6 里那些「背红面积」是 `RED_LUT`（gradient map）时代的量。现在六个面各有
自己的像素处理，背面改用硬阈值双色（`DUOTONE_*`，douyin 屏录实测：深蓝 57% /
白 43%，中间调占比 **0%** → 硬切），`RED_LUT` 已从 `effects.py` 删除。
§3.6 / §3.7 的「背」面指标是**几何投影面积**，与配色无关，仍然有效。

删之前的两组测量值记在这里，要还原原片保真度直接取用：

- **原片逐像素实测**：一条很窄的暗红带，灰 60 → 亮度 52.7，灰 160 → 82.0，
  全域跨度仅 60。**比 `source_dim=0.65` 压过的背景还暗**（灰 160 处背景 104
  vs 红面 82）——翻过去了也读不出来，用户反馈的「看不到后面」有一半是这个。
- **改良版**（退役前实际在用的）：保持红相（红度 @灰110 从 54 提到 169），
  动态范围拉到 174，每一档都亮过背景。`_build_lut` 控制点（灰阶, BGR）：
  `(16,(24,20,58))` `(48,(32,26,112))` `(80,(38,30,168))` `(112,(46,36,212))`
  `(144,(58,46,238))` `(176,(84,68,250))` `(216,(134,116,254))`
  `(255,(190,180,255))`

通用教训：**面的配色要跟 `source_dim` 压过的背景比，不是跟纯黑比。**

## 4. 为什么换掉旧的「四指各握一角」

旧架构：`前上=食指 / 前下=拇指 / 后上=中指 / 后下=小指`，8 个角各自独立跟指尖。

拿原片 374 个双手帧样本实测长方体**数学上必须相等**的棱：

| | 旧架构 | 新架构 |
|---|---|---|
| 端面两条深度棱 比值 | 中位 **1.56**，p90 2.94，最大 13.5 | 中位 1.13，p90 1.17，最大 1.40 |
| 两端前棱 比值 | 中位 **1.50**，p90 2.62 | **1.0000**（恒等） |

死结在于：顶深棱 = 食指尖→中指尖（**相邻两指，30–60 px**），
底深棱 = 拇指尖→小指尖（**全手最远两点，150–250 px**）。
同一条棱被绑在量级差 4–8 倍的两个解剖量上，`BOX_RIGID` 只归拢方向
（注释写着「长度原样保留」），**楔形在那个架构里无解**。

新架构剩下的 1.13 是**真实的透视前缩**（顶深棱离相机更近所以投影更长），物理正确。

驱动点也换了：旧版用食指/中指/小指/拇指四个 **TIP**——21 点里噪声最大、
最容易被遮挡的四个；翻手做效果时手指正好蜷曲遮挡，MediaPipe 开始瞎猜，角就飞。
新版指尖只出「锚点 + 一个展开量标量」，顶点全部由刚体参数生成。

## 5. 随之删掉的东西

刚性和透视变成构造出来的以后，下面这些补丁全部无用：

- `BOX_PERSP`（后框向质心收缩）→ 真透视代替
- `BOX_RIGID`（深度棱方向正则化）
- `BOX_DIR_SMOOTH` + 每手卷向 EMA
- `NSIGN_HYST` + n̂ 符号滞回（ψ 是连续角，不做符号决策）
- `_end_state` 里按 track_id 键控的 8 维标量组 → 只剩全局 (盒高, ψ, 长轴深度比) 三个标量的 EMA
- `_tri_sign`（2D 绕序判可见性）→ 3D 外法线，物理正确
- 无名指跨手弦线（理由是「中指/小指已各自拥有实体棱」，新模型里不成立；原片也没有这条线）

## 6. 已知边界

- **端面在早期版本里永不可见**（已被 `BOX_AXIS_Z_GAIN` 解除）：长轴锁在像平面内时，
  两个端面的外法线只有 ±x 分量，相机在 `x=0` 平面上 → 结构上不可能朝向相机。
  加入长轴深度分量后端面可以露出来——原片实测右端面出现 **21 帧**
  （`顶+右+前` 等组合）。原片帧 312 那一帧确实只有蓝顶+绿前
  （左端那块黄绿色是绿前面采到亮窗户的结果，不是端面）。
- **`BOX_ROLL_EXPO` / `BOX_AXIS_Z_GAIN` 未标定**：原片有盒子那段拍不到手，
  没法反解「掌面朝向 → roll」和「掌宽比 → 长轴深度」这两条映射。实拍时用
  live 的 `[` `]` 调 expo。（`BOX_ROLL_GAIN` 已随线性映射一并退役，见 §3.6。）
- **`_orient` 是 cos 型的非单调信号**：一整圈里走 `0→+1→0→−1`，所以一直往
  一个方向翻，盒子转到某个角度后会自己往回转。这是信号本性，限幅和映射都
  治不了，要根治得换成多 landmark 联合估计。**动它之前必须先录一段真实的
  「双手握盒连转 2~3 圈」素材** —— `assets/sample.mp4` 是「翻一只手拧麻花」，
  与该动作完全不同，历史上两次在这上面验证通过、实机翻不动。
