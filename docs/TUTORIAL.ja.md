## 0. 必要なもの

| 項目 | 条件 | 補足 |
|---|---|---|
| パソコン | macOS（実機確認済み）。Apple Silicon なら余裕 | M4 Pro の 1080p で、検出 6.9 ms/フレーム、一番重いスタイルの描画が p95 で 6.5 ms。30 fps に対してだいぶ余裕があります。Intel Mac は動くはずですが測っていません。Linux / Windows は**未確認**（[11](#11-よくある質問) の末尾） |
| カメラ | 内蔵で十分 | 1080p が理想。720p でも動きます（エフェクトの大きさは画面に合わせて変わる） |
| Python | 3.12〜3.14 | `mediapipe` の wheel は新しい Python への対応が遅れがち。入らなければ 1 つ下のバージョンへ（CI は 3.12 固定、手元の開発は 3.14） |
| ネットワーク | 初回だけ | 依存のインストールと 7.5 MB の MediaPipe 手モデルのダウンロード。以降はオフラインで動く |
| ffmpeg | 任意 | 録画のフレームレート補正と、オフライン描画の h264 変換にだけ使う。なくても動く |

依存は `mediapipe`、`opencv-contrib-python`、`numpy` の 3 つだけ（バージョン範囲は `requirements.txt`。上限を次のメジャーに固定してある理由もそこに書いてあります）。

## 1. インストールと初回起動

### 1.1 ワンコマンド（おすすめ）

```bash
git clone https://github.com/Eureka0w0v0/manual-tracking.git
cd manual-tracking
./run.sh
```

初回の `run.sh` は、`.venv/` を作る → `requirements.txt` を入れる → `PYTHONPATH=src` を設定 → `live --style cube` を起動、という流れ。
2 回目以降は最後の一歩だけです。

初回起動時にはモデルも `models/hand_landmarker.task` へ自動ダウンロードします（Google 公式のバージョン付き URL なので中身は変わらない。落としたあと sha256 を照合し、合わなければ削除してエラーにします。プロキシによる差し替えや CDN のエラーページ対策です）。

### 1.2 カメラの許可（macOS）

初回は「"ターミナル" がカメラにアクセスしようとしています」と聞かれるので **OK** を押します。出なかった、間違えて押した、という場合は
システム設定 → プライバシーとセキュリティ → カメラ → 使っているターミナル（Terminal / iTerm / VS Code）をオンに。

**`start-live.command` をダブルクリック**する手もあります。自動選択した内蔵カメラから 1 フレーム取って許可ダイアログを出してから起動します。

> iPhone の「連係カメラ」がつながっていると、OpenCV のデバイス 0 が iPhone になることがあります。選ばれると iPhone の画面が点いて乗っ取られます。
> デフォルトの `--camera -1` は `system_profiler` の一覧を順に見て、iPhone/iPad でない最初のデバイスを選ぶので、普通は内蔵カメラになります。

### 1.3 手動インストール（環境を自分で管理したい人向け）

```bash
python3 -m venv .venv
.venv/bin/pip install -U pip
.venv/bin/pip install -r requirements.txt
PYTHONPATH=src .venv/bin/python -m manual_tracking live --style cube
```

パッケージはあえて `pip install -e .` しない設計です（`pyproject.toml` の 1 行目参照）。なので `PYTHONPATH=src` は必須。
それと `src/manual_tracking/__main__.py` は相対 import なので `python -m manual_tracking` でしか動きません。`python __main__.py` は必ず `attempted relative import with no known parent package` で落ちます。

### 1.4 IDE

- VS Code なら、リポジトリ同梱の `.vscode/` がそのまま使えます。`Cmd+Shift+B` でデフォルトスタイルを起動、`F5` でデバッガ付き起動（リアルタイムループは debugpy でフレームレートが落ちるので、`Ctrl+F5` のデバッガなしがおすすめ）。テストパネルから `tests/` も直接走ります。
- それ以外の IDE は、リポジトリ直下の `main.py` を開いて実行ボタンを押してください。やっていることは一つだけで、`src/` を `sys.path` に入れてからパッケージとして import する、つまり相対 import の制約を IDE 向けに回避しているだけです。引数はいつも通り `python main.py live --style mirror`。

### 1.5 終了

ウィンドウにフォーカスがある状態で `Q` か `Esc`。ターミナルで `Ctrl+C` でも大丈夫です。後片付けは 録画ファイル → カメラ → ウィンドウ → 検出スレッド → モデル の順で、どれか一つが失敗しても残りは止まりません（録画の途中で強制終了しても、開けない mp4 は残らない）。

## 2. 画面に出ているものの意味

### 2.1 起動時のバナー（ターミナル）

```
========================================================
  MANUAL TRACKING LIVE — 折纸镜面 / 彩色玻璃盒 / 悬浮立方体
  拇指+食指捏纸；翻转一只手拧麻花；捏死压成细线
  采集 1920x1080 (req 1920x1080)  帧率 30 (req 30)  推理边 全帧
  窗口 1920x1080 (可拖拽边角缩放)
  Q退出  S风格  D暗底  R录制  o p 底亮度
  screen 调参: [ ] 翻转曲线  ; ' 挂多高  , . 旋转轴  - = 锚点跟手  < > 收起距离  7 8 角速度上限
  screen/cube: 9 0 旋转跟手  g h 通透  { } 棱线
  cube  键位: F 重力开关  X 归位
  cube  手势: 捏在盒上拖=转 | 双手捏住=移动+缩放+拧 | 张开手=炸开
========================================================
```

バナーは中国語です。[4](#4-リアルタイム調整) のキー表がその訳になっています。

- `采集 … (req …)` は、カメラが**実際に**返してきた解像度とフレームレート、と要求した値。デバイスは能力と明るさで勝手に決めます。暗い部屋だと自動的に 15 fps まで落ちます。
- キーの行は手書きではなく、`live.py` のキー表から生成しています。実行時に出る「このキーは今のスタイルでは使えない」というメッセージも同じ表から出ます。

### 2.2 HUD（ウィンドウ上部の黒い帯）

```
FPS  30.1  det   6.9ms  draw  4.2ms  hands:2  cube  idle  size 180 grip1 open0.62  顶+前+右
```

| 項目 | 意味 |
|---|---|
| `FPS` | 表示フレームレート（EMA。最初の 5 フレームは数えません。起動直後の 1 フレーム目は異常に遅く、これを種にするとしばらく値が狂うため） |
| `det` | 直近の MediaPipe 検出にかかった時間（ワーカースレッドで動くので画面は止まらない） |
| `draw` | 描画時間（EMA） |
| `hands:N` | このフレームで使った手の数 |
| スタイル名 | 現在のスタイル |
| `busy` / `idle` | 検出スレッドが今推論中かどうか |
| `ERRn` | 検出が例外を投げた累計回数。**出た時点で異常**です。最初の例外はターミナルに出ています。このカウンタがないと、検出が死んでいても `hands:0` にしか見えず「本当に手がない」のと区別がつきません |
| `REC` + 右上の赤丸 | 録画中 |

そのあとにスタイル固有の情報が続きます。

- cube では、`size` 辺の長さ px、`grip` キューブをつかんでいる手の数、`open` つまんでいない手の開き具合（分解表示の駆動量、しきい値 0.70→1.05）、そして**今カメラを向いている面**（`顶+前+右` = 上+前+右）または `explode`。
- screen では、5 つのつまみの現在値 `expo lift bias resp cap`、`psi` 箱の長軸まわりの角度、`oL oR` 両手のひらの向き（回転を駆動する生の信号、−1〜1）、`dz` 長軸の奥行き成分、そして可視面。
  回転を調整するとき、「幾何が回っていない」のか「回ったが読めない」のかをこれで見分けます。

HUD は OpenCV の Hershey フォントで描いていて、**ASCII しか出せない**のでこういう略語になっています。面の名前は漢字 1 文字で、顶 = 上、前 = 前、背 = 後、底 = 底、左 = 左端、右 = 右端。

### 2.3 映像

- カメラ背景はデフォルトで明るさ 55 % に落としてあります（`D` で黒背景、`o`/`p` で明るさ調整）。主役はエフェクトなので。
- 骨格は、1 つ目の手が金色、2 つ目がオレンジ。指先の点はほかの関節より一回り大きい。
- 映像はデフォルトで**左右反転**（鏡を見ているのと同じで、左右の感覚が合う）。`--no-mirror` で切れます。

## 3. 3 つのスタイルの遊び方

`S` キーで `mirror → screen → cube` の順に回ります。`--style` で直接指定も可。

まず全スタイル共通の、手の映し方のコツから。

- 手が画面の高さの **1/4〜1/2** を占めるくらいが一番安定します。遠いとランドマークが震え、近いと指が画面から出ます。
- カメラに正対して、光は前から。逆光と真上からの光は MediaPipe が手を見失いやすい。
- 背景がごちゃごちゃしていると検出が遅くなります。`det` が 15 ms を超えたら座る場所を変えたほうが早い。
- 両手を長く重ねない。お互いに隠れると MediaPipe がたまに片手しか認識しません。両手モードには 8 フレームの猶予、トラックには 250 ms の保持がありますが、それを超えると取り直しです。

### 3.1 cube 浮遊キューブ（デフォルト）

ほかのスタイルと根本から違って、**キューブ自身が位置・向き・大きさを持っています**。手はそれを押したり回したりするだけ。離せばその場に残ってゆっくり自転し続ける（約 10°/秒）、目の前に本当に浮いている物のような挙動です。

| やりたいこと | やり方 | 裏側の判定 |
|---|---|---|
| つかむ | 親指の先と人差し指の先を**つまんで**、つまんだ点がキューブの上にあるようにする | つまみ = 2 本の指先の距離 / 手のひら幅 < 0.42（離すには > 0.62 が必要。間はヒステリシスで、境界でばたつかない）。つまんだ点 = 2 本の指先の中点で、中心から ±0.75 辺長の範囲に入っていないとつかめません。**空中でつまんでも何も起きない**。つかんだ瞬間、つまんだ点から波紋が出ます（つかめた合図） |
| 面をめくる | 片手でつかんで**ドラッグ** | 横に引けば縦軸まわり、縦に引けば横軸まわり、1 px ≈ 0.009 rad（349 px で 180°）。手のひらの向きではなくドラッグの差分で回すので、同じ方向に引き続ければ無限に回り、勝手に戻ってくることはありません |
| 移動 / 拡大縮小 / ひねり | **両手で**つかむ | キューブは両手の中点に 1:1 でついてきます（割引なし）。両手の距離を何倍かに広げると辺もその倍率で伸びる（画面短辺の 6 %〜60 % に制限）。ハンドルを回すように両手を回すと画面法線まわりに回転（ドラッグでは届かない第 3 軸） |
| 分解して 6 面を見る | つまみを離して**五本指を開く** | 開き具合 = 人差し指先〜小指先の距離 / 手のひら幅。0.70 以下で閉じ、1.05 以上で全開。6 面がそれぞれの法線方向に飛び出して浮かびます。握るか手を下ろせば戻る |
| 投げる | ドラッグ中に手を離す | 運動量を持ったまま動きます。回転は滑り続け（摩擦 0.85/フレーム、1 秒ほどで止まる）、移動は流れ続け、**画面の端で跳ね返る**。強く投げるとちょうど一面分回ります |
| 重力 | `F` | 離した瞬間から放物線で落ちて、床で跳ね、床の摩擦で転がって止まる。もう一度押せばオフ |
| ぐちゃぐちゃになった / 端に押し込んだ | `X` | 姿勢が画面中央にリセットされる |

操作感の細かいところ（すべて `floatcube.py` の先頭で変えられます）：

- つかんだあとは**どこへ引いてもついてきます**。つまんだ点がキューブの外に出ていても構いません（両手で拡大すると必ず手は箱の外に出る）。つまみを離したときだけ外れます。
- 検出が 0.25 秒ほど途切れても外れません。1 フレームだけの「離した」スパイク（手首を返すとき指先が自分の手の甲に隠れて、ランドマークが一瞬飛ぶ）は無視して、3 フレーム連続でないと離したと認めません。
- 両手モードで片手を見失うと、8 フレームの猶予の間は**止まったまま**です。片手モードに落ちていきなり回り出す、ということはありません。

### 3.2 screen ガラスの箱

**両手を開いて、見えない直方体を抱えているように構えます。** 箱は両手のノイズの少ないパラメータ数個から「組み立て」られます。

- 両手のアンカー（手のひら中心から指先の弧の中点へ 85 % の位置）を結ぶ線 = 長軸、その長さ = 箱の長さ。
- 指先の広がり（人差し指先〜小指先）× 1.14 = 箱の高さ、奥行き = 1.47 × 高さ。
- 手のひらの向き（手首を返す）→ 長軸まわりの**回転**。
- 両手の**手のひら幅の比** → 長軸の奥行き成分。片手をカメラ側に突き出すと箱が画面の外を向いて、端の面が見えます。

手が頂点を固定しないので、箱は常に剛体で、透視も常に正しい（旧版は 8 つの角がそれぞれ指先を追っていて、くさび形になるのを直しようがなかった。経緯は [`GLASS_BOX_GEOMETRY.md`](GLASS_BOX_GEOMETRY.md)）。

| やりたいこと | やり方 |
|---|---|
| 箱を出す | 両手を開いて、40 px 以上離し、指先はだいたい上向き |
| 裏を見る | **手首を返す**（手のひら ↔ 手の甲をカメラに向ける）。両手の向きを平均するので、両手同時に返すのが一番すっきり |
| 端の面を見る | 片手を前に出し、もう片方を引く |
| しまう / 出す | 両手の最近点が手のひら幅の 0.35 倍未満まで近づくと 0.17 秒でつぶれて消える。0.75 倍以上に離すと伸びて戻る（ヒステリシスがあるので境界でちらつかない） |

6 面 6 種類の処理で、ひと目で区別がつきます。

| 面 | 処理 |
|---|---|
| 上 | 青の反転グラデーションマップ + 横縞グリッチ |
| 前 | リソグラフ風 2 色刷り（版ずれの縁 + ディザ） |
| 後 | ハードしきい値の 2 色（シルクスクリーン） |
| 底 | 点群 / ホログラム（局所コントラストを疑似深度に） |
| 左端 | 四分木の適応モザイク |
| 右端 | ハーフトーン |

**既知の限界**が一つ。手のひらの向きは cos 型の信号で、一周する間に `0→+1→0→−1` と動きます。だから同じ方向に返し続けると、ある角度で箱が戻ってきます。信号の性質なので仕方がない。無限に回したいなら `cube` を。

### 3.3 mirror 折り紙ミラー

**それぞれの手で、親指と人差し指で紙の角をつまみます。** 左手の人差し指先 = 左上、左手の親指先 = 左下、右手はその鏡像。

- 平らに持つと、反転ミラーの紙（`clamp(283 − 0.56 × 背景)`。背景がネガのゴーストのように透ける）。
- **片手を返す**と、その半分が暗くなって冷たいグレーに寄り、サンプリング点が外へずれます。紙が折れた感じ。
- 両手をずらして上辺と下辺が交差すると、紙が 2 枚の三角形の翼にねじれ、右の翼が手前に。
- **両手ともつまみ切る**（つまみ距離 < 16 px）と、紙が真横を向いて、隙間を挟んだ白い線 2 本だけになります。

## 4. リアルタイム調整

どのキーも**メモリ上のフィールド**を変えるだけで、終了すればモジュール先頭の定数に戻ります。恒久的に変えたいなら [7](#7-パラメータを変えるどのファイルのどの行か) へ。

今のスタイルで使えないキーを押すと、ターミナルに `[ 只对 screen 有用 (当前 cube)`（「screen 専用（今は cube）」）と一言出ます。画面に影響しない値を黙って書き換えることはしません。

### 全スタイル共通

| キー | 動作 |
|---|---|
| `S` | スタイル切り替え |
| `D` | カメラ背景 ↔ 黒 |
| `o` `p` | 背景の明るさ（1 回 0.05） |
| `R` | 録画のオン / オフ |
| `Q` / `Esc` | 終了 |

### screen と cube で共通

| キー | パラメータ | ひらたく言うと |
|---|---|---|
| `g` `h` | `face_alpha` | ガラスの透け具合。正面を向いた面の不透明度 0.25〜1.0、内側の壁は 0.42 倍でついてくる |
| `{` `}` | `box_edge_w` | 稜線の太さ px。0 で継ぎ目なし（デフォルト）。元動画は 4 px の白線ですが、各面に質感が付いた今は白線のほうが目立ってしまう |
| `9` `0` | screen: `roll_resp` / cube: `orbit_gain` | 回転の追従度。screen は 0.05 ずつの加算、cube は 1 桁の幅があるので ×1.15 の乗算 |

### screen だけ

| キー | パラメータ | ひらたく言うと |
|---|---|---|
| `[` `]` | `roll_expo` | 反転カーブの急さ。小 = 敏感、大 = 中央が鈍く静止時は安定。ノイズ対策のつまみ**ではありません**（次の行を参照） |
| `7` `8` | `roll_max_rate` | 角速度の上限 °/フレーム。「色のちらつき」を抑える主役はこれ。手のひら向き信号が飽和域で符号反転したときの瞬間移動を止めます。デフォルト 10 = 300°/秒で、実際の手の速さより上。8 だと本物の動きまで削ってしまう |
| `;` `'` | `anchor_lift` | 箱をぶら下げる高さ。0 = 手のひら中心（低い）、1 = 指先の弧の中点（元動画の位置）、デフォルト 0.85 |
| `,` `.` | `depth_bias` | 長軸まわり回転の不動点。0 = 前面が手の上、0.5 = 中心（デフォルト、箱全体が手を軸に回る）、1 = 背面 |
| `-` `=` | `anchor_resp` | アンカーの追従度。大 = ついてくる、小 = 安定だが鈍い。手が速く動くと自動で緩む（速度適応） |
| `<` `>` | `gap_shut` | 両手をどこまで近づけたら箱をしまうか（手のひら幅で正規化しているので、カメラとの距離に依存しない）。再表示のしきい値はこれ + 0.40 |

### cube だけ

| キー | 動作 |
|---|---|
| `F` | 重力のオン / オフ |
| `X` | 姿勢リセット |

## 5. 録画

- `R` で開始、もう一度 `R` で停止。ファイルは `output/live_YYYYmmdd_HHMMSS.mp4`、**HUD は入りません**。
- `--record path.mp4` を付けると、最初の録画だけそのパスに書きます。以降の `R` は自動命名で、撮ったばかりのテイクを上書きすることはありません。
- コンテナのフレームレートは録画開始時点の実測 FPS（10〜60 に制限。起動直後 15 フレームのウォームアップ中は 30 に固定。そうしないと 1 フレーム目の 6 fps くらいの値がコンテナに焼き付いて、67 % のスローモーションになる）。
- 停止時、実際の平均フレームレートがコンテナと 5 % 以上ずれていて（暗い部屋でカメラが 15 fps に落ちるのはよくある）、しかも 1 秒以上撮っていれば、ffmpeg で本当のレートに**再多重化**します（`-c copy`、再エンコードなし）。ffmpeg がなければ「スキップした」と出ます。ファイル自体は再生できて、速度だけ合いません。

## 6. コマンドライン完全リファレンス

サブコマンドは 3 つ。引数なし = `live`（スタイルは `live.DEFAULT_STYLE`、今は `cube`）。

### `live` リアルタイム

```bash
./run.sh live [--style S] [--camera N] [--width W --height H] [--fps F]
              [--window-scale K] [--infer-size N] [--source-dim D]
              [--no-source] [--no-mirror] [--no-filter] [--model PATH] [--record PATH]
```

| オプション | デフォルト | 意味 |
|---|---|---|
| `--style` | `cube` | `mirror` / `screen` / `cube`。旧名 `fabric`→mirror、`track`→screen も可 |
| `--camera` | `-1` | カメラ番号。−1 = 内蔵を自動選択（iPhone 連係カメラを避ける） |
| `--width` `--height` | 1920 × 1080 | 要求するキャプチャ解像度。デバイスが別のサイズを返してきたらこのサイズにリサイズして、エフェクトの座標系を揃える |
| `--fps` | 0（=30） | **要求**フレームレート。60 はカメラ側の対応が必要。検出は中央値 6.9 ms なので 60 Hz でも追いつく |
| `--window-scale` | 1.0 | ウィンドウの初期サイズ倍率。ウィンドウ自体は角をドラッグして変えられる。表示にだけ影響 |
| `--infer-size` | 0 | MediaPipe 推論の長辺。0 = フル解像度。**Apple Silicon ではフル解像度が一番速くて誤差も小さい**ので、推論が本当に遅いマシンでだけ 640 などにする |
| `--source-dim` | 0.55 | 背景の明るさ 0〜1 |
| `--no-source` | | 黒背景 |
| `--no-mirror` | | 左右反転しない |
| `--no-filter` | | One Euro の時間フィルタを切って生のランドマークを見る（震えます。デバッグ用。このモードではフレームをまたぐトラック id がない） |
| `--model` | 自動 | 使う `.task` モデル。明示したときは**自動ダウンロードしない**ので、ファイルがなければエラー |
| `--record` | | 起動後最初の録画の出力先 |

### `run` 動画をオフラインで描画

```bash
./run.sh run -i input.mp4 -o output.mp4 [--style S] [--source-dim 0.35] [--no-source] [--no-filter] [--max-frames N] [--model PATH]
```

フレームごとに検出 + 描画して `mp4v` で書き出し。ffmpeg があれば h264 + `faststart` に変換します（プレイヤー互換のため）。
オフラインのデフォルトはスタイル `mirror`、背景 0.35（作品としてはエフェクトが主役で、映像は環境）。
`cube` はオフラインではあまり意味がありません。誰もつまんでくれないので自転するだけです。

### `dump` 21 点を JSON に書き出し

```bash
./run.sh dump -i input.mp4 -o landmarks.json [--model PATH]
```

After Effects / TouchDesigner / 自作スクリプト向け。

```json
{
  "width": 1920, "height": 1080, "fps": 30.0, "video": "input.mp4",
  "frame_count": 358,
  "frames": [
    {
      "frame": 0,
      "hands": [
        {"handedness": "Right", "score": 0.98,
         "points": [[x_px, y_px, z_norm], "... 全 21 点、MediaPipe の順（0 手首 … 4 親指先 … 8 人差し指先 … 20 小指先）"]}
      ]
    }
  ]
}
```

`x_px`/`y_px` は**フル解像度のピクセル座標**（One Euro フィルタ適用済み）。`z_norm` は MediaPipe の生の相対深度（フィルタは xy だけで、z は素通し。参照系が混ざらないように）。手は `Right` が先、`Left` が後の順。

## 8. どう動いているか（アーキテクチャ案内）

### 8.1 データの流れ

```
カメラ ──cap.read()──▶ メインスレッド                                    ウィンドウ
                        │ 反転 / リサイズ                                    ▲
                        ├─submit(frame)──▶ 検出スレッド (detect_service)      │ imshow
                        │                    │ MediaPipe HandLandmarker
                        │                    │ tracker: トラック照合 + One Euro + 利き手ラッチ
                        │                    └─▶ 直近 2 回の結果（タイムスタンプ付き）
                        ├─latest_pair() ◀────┘
                        ├─extrapolate(): ランドマークの速度を「今」まで外挿
                        ├─renderer.render(frame, hands)
                        │    ├─ cube:   floatcube.update → project → 6 面を塗る
                        │    ├─ screen: glassbox.solve → 6 面を塗る
                        │    ├─ mirror: sheet
                        │    └─ 骨格
                        ├─recorder.write(out)      ← HUD を描く前に録画
                        └─HUD → imshow → waitKey → キー表で振り分け
```

「手についてくる」感じを作っているのは 2 つの決定です。

1. 検出が画面を止めない。MediaPipe はワーカースレッドで動き、メインスレッドは毎フレーム最新のフレームをコピーなしで渡します（latest-wins の郵便箱。ワーカーは最新の 1 枚だけ処理し、古いのは捨てる）。検出レート = 1/max(検出時間, フレーム間隔) で、キューに引きずられて遅くなることがない。
2. 表示時刻への外挿。検出結果は画面より常に 1〜2 フレーム遅れています。メインスレッドは直近 2 回の結果をトラック id で対応づけて速度を出し、ランドマークを「今」まで進めます（最大 80 ms、減衰 0.7、1 点あたり 40 px 上限で吹っ飛ばない）。検出レートが表示レートを下回ったときの階段状のカクつきはこれで消えます。

### 8.2 トラッキング層（`tracker.py`）

- 手ごとに**持続するトラック**（`track_id`）。フレーム間の対応づけは手首の距離による 2×2 の最適割り当てで、しきい値は手のひら幅に応じて変わります。一瞬見失った手はトラックを 250 ms 保持（壁時計基準で、フレーム数ではない。マシンが引っかかった瞬間にフレーム数はあてにならなくなる）。
- 固定 EMA の代わりに **One Euro** フィルタ。静止時は強く平滑化し、速く動くと自動で緩む。フィルタは xy だけ、z は素通し。
- **利き手ラベルはトラックに固定**。MediaPipe は毎フレーム独立に左右を判定するので、手首を返す途中で 1 フレームだけ反転します。同じトラックは同じ手なのだから、ラベルは 5 フレーム連続で食い違ったときだけ切り替える。最初のフレームのラベルは信用しない（検出したての手が一番誤判定されやすい）ので、最初から 1 票足りない状態で始めます。

### 8.3 描画側の分担

```
paths ──▶ landmarks ──▶ tracker ──▶ handgeom ──▶ boxgeom ──▶ glassbox / floatcube
                                                     │                │
                                     effects ──▶ paint ──▶ sheet ──▶ renderer ──▶ detect_service ──▶ live ──▶ __main__
```

| モジュール | やることは一つ |
|---|---|
| `landmarks.py` | MediaPipe の 21 点のインデックスと骨の接続表 |
| `handgeom.py` | 手 → ノイズの少ないスカラー / アンカー数個（手のひら中心、つまみ、手のひらの向き、指先の広がり、手のひら幅）。キャンバスには触らず、箱の存在も知らない |
| `boxgeom.py` | 直方体の頂点順 + 弱透視投影。`screen` と `cube` が共有する**唯一**のコピー |
| `glassbox.py` | 両手のパラメータ → 剛体直方体の 8 頂点（フレームをまたぐフィルタ状態込み）。キャンバスには触らない |
| `floatcube.py` | 姿勢を持つキューブ。つかみ判定、ドラッグ / 両手 / 慣性 / 重力 / 分解の状態機械。キャンバスには触らない |
| `effects.py` | 6 種類のピクセル処理（`src → out` の純関数。パラメータは生成時にルックアップテーブルへ焼き込む）。「手」のことは一切知らない |
| `paint.py` | 多角形を「何かの処理を通した背景」で塗る（bbox 局所ウィンドウ + マスク + アルファ + 陰影）。手も箱も知らない |
| `sheet.py` | 折り紙ミラー（箱を持たない唯一のスタイル） |
| `renderer.py` | スタイル別の振り分け。`screen`/`cube` の面の並べ替え（3D 外向き法線による可視判定 + 遠い順 + Lambert 照明）。背景キャッシュ。左右役割のヒステリシス |
| `detect_service.py` | 検出スレッド + 外挿 |
| `live.py` | カメラ、録画、HUD、キー、メインループ |
| `pipeline.py` | オフラインの動画 → 動画 / JSON |

依存は右向きにしか向かいません。ruff の isort ルールが、副作用として import の順序をこの線に固定しています。

### 8.4 性能（1920×1080、実際のランドマーク、M4 Pro）

| スタイル | 描画 平均 | p95 |
|---|---|---|
| mirror | 0.66 ms | 0.88 |
| cube | 3.55 | 5.21 |
| screen | 4.05 | 6.49 |

検出（中央値 6.9 ms）は別スレッド。33 ms のフレーム予算の 1/5 も使っていないので、ホットパスにはもう手を入れる価値のある場所がありません。各エフェクトの docstring に、何 ms から何 ms に縮めたか、何を試して効かなかったかが書いてあります。

## 9. 開発：4 段階のチェックと CI

```bash
.venv/bin/pip install -r requirements-dev.txt                # ruff + pytest
.venv/bin/ruff check main.py src tools tests                 # 1. 静的チェック（isort 込み）
.venv/bin/pytest                                             # 2. テスト: 158 件、1 秒未満、カメラ / 素材 / モデル不要
PYTHONPATH=src .venv/bin/python tools/cube_check.py          # 3. cube 操作感のボトムライン: 27 アサーション、合成の手
PYTHONPATH=src .venv/bin/python tools/e2e_check.py           # 4. screen の回帰: サンプル動画 + モデルが必要、約 1 分
```

| 段階 | 何を止めるか |
|---|---|
| テスト（`tests/`） | 「変更を間違えて落ちる」: 面トポロジと頂点順の整合、エフェクトのサイズ / 不変契約、箱の剛性、別名表、利き手ヒステリシス、外挿と録画フレームレート、キーのスタイル分け、入口のデフォルト、モデル DL の検証、終了時の後片付け |
| 操作感（`cube_check`） | 引けない、戻ってくる、離すとふらつく、画面外にはみ出す |
| 回帰（`e2e_check`） | 「変更で悪くなった」: **可視面が毎秒 5 回切り替わるような色のちらつき**、背面が読めない。`tests/` が全部緑でもこれは見えない |

前の 3 つは push のたびに GitHub Actions で回ります（`.github/workflows/ci.yml`、ubuntu + Python 3.12）。4 つ目はローカル専用。

サンプル動画について。`assets/sample.mp4` はリポジトリに入っていません（元の作者の動画なので）。4 段階目を回すには、両手を返す 1080p/30fps の動画を自分で撮ってそのパスに置いてください。ドキュメントの数値はすべて元動画で測ったものなので、素材を替えたら

```bash
PYTHONPATH=src .venv/bin/python tools/e2e_check.py --sweep   # expo × cap のグリッドをスイープ
```

を回して、グリッドを見てから `tools/e2e_check.py` 先頭の 3 つのしきい値を動かすか決めてください。あれが守っているのは「体感の赤線を越えたか」であって、「前回と同じか」ではありません。

`tools/synth.py` は `tests/` と `cube_check` が共用する合成の手です。21 点すべてを実際の手の比率で並べてあります（1 点でも `(0,0)` のままだと手のひら中心が画面左上に引っ張られて、測った「追従度」が嘘になる。しかもエラーは出ない）。

コミットの習慣について。ひとまとまりの変更は**テーマごとに分けて**コミットし、メッセージは中国語の conventional commits（`feat:` / `fix:` / `refactor:` / `docs:` / `test:` / `build:` / `ci:` / `chore:`）、本文には**なぜ**を書きます。何が壊れていたか、実測値はいくつだったか。`git log` がそのままこのプロジェクトの設計書です。

## 10. スタイルを追加する

仮に `glow` という名前だとして：

1. `src/manual_tracking/glow.py` に `draw(canvas, frame_bgr, ...)` を書く。受け取るのは左右に振り分け済みの手だけ（役割のヒステリシスは renderer の仕事）。調整用の定数はモジュール先頭に、出どころを添えて。塗りは `paint.fill`、ピクセル処理は `effects.FaceEffect`（`src → out` の純関数）として書く。
2. `renderer.py` の `STYLES` に名前を足し（順序 = `S` キーの巡回順）、`render()` に分岐を足す。旧名を残したければ `STYLE_ALIASES` へ。
3. 専用キーが要るなら、`live.py` の `_KNOBS`（±ステップ）か `_ACTIONS`（それ以外の形）に `styles=("glow",)` 付きで追加。バナーと「スタイル違い」メッセージは自動でついてくる。キーが重複すると起動時に落ちます。
4. テスト。`tests/test_registry.py` はレジストリを自動で見ます。`tests/test_render_smoke.py` に「合成の手を入れて落ちない、画面が実際に変わる」ケースを 1 つ足す。
5. README のスタイル一覧とキー表に行を足して、4 段階のチェックを回す。

## 11. よくある質問

**カメラが開けない / `打不开摄像头 #0`**
許可（[1.2](#12-カメラの許可macos)）。ほかのプログラムが掴んでいる（Zoom、OBS、ブラウザのタブ）。`--camera 1` で別の番号を試す。
iPhone をつなぐと番号がずれます。デフォルトの自動選択は避けてくれますが、手動指定のときは注意。

**手が画面に映っているのに `hands:0`**
光（前から）、距離（手が画面の高さの 1/4〜1/2）、端に寄せない。HUD に `ERRn` が出ているなら「見えていない」のではなく検出が**落ちています**。ターミナルに最初の例外が出ているはずで、たいていはモデルファイルの破損（`models/` を消して再ダウンロードさせる）。

**カクつく / `FPS` が 15 に落ちる**
まず HUD を見る。`det` が高い → マシンが遅い。`--infer-size 640` か `--width 1280 --height 720` を試す。`draw` が高い → ほぼありえない（[8.4](#84-性能19201080実際のランドマークm4-pro)）。デバッガが付いていないか確認。どちらも高くないのに FPS が低い → カメラが暗さで勝手にレートを落としている。照明をつける。

**`attempted relative import with no known parent package`**
`src/manual_tracking/__main__.py` を直接実行しています。`./run.sh`、`python main.py`、`python -m manual_tracking` のどれかで。

**`ModuleNotFoundError: No module named 'manual_tracking'`**
`PYTHONPATH=src` がありません（`run.sh` / `main.py` / `.vscode` は設定してくれます。手で動かすときは自分で付ける）。

**`模型校验失败: sha256 … ≠ 预期 …`**（モデルの検証失敗）
落ちてきたのが公式モデルではない（会社のプロキシ / 学内ネットワークの差し替え / CDN のエラーページ）。自動で削除済みです。別のネットワークで再実行するか、コメントにある URL を手で落として `models/hand_landmarker.task` に置くか、`--model` で自分のファイルを指定。

**`import cv2` でエラー / 挙動がおかしい**
同じ環境に `opencv-python` と `opencv-contrib-python` が両方入っていると上書きし合います。`pip uninstall opencv-python` で contrib だけ残す（mediapipe が依存しているのはそちらで、`live` にはその GUI が要る）。Linux で `import cv2` が `libGL.so.1` がないと言う場合は `apt install libgl1 libglib2.0-0`。

**録画した動画が早回し / スロー**
ffmpeg を入れてください（`brew install ffmpeg`）。停止時に本当のフレームレートへ再多重化します。[5](#5-録画) を参照。

**箱（screen）の色がずっとちらつく**
まず `7` で `roll_max_rate` を 8 まで下げて、収まるか見る。収まるなら、手の速さや照明のせいで手のひら向き信号が飽和域で符号反転しています。`docs/GLASS_BOX_GEOMETRY.md` §3.7 に分析があります。`roll_expo` は触らないこと。あれはノイズ対策のつまみではありません。

**Linux / Windows で動く？**
未確認です。macOS 固有の箇所は 2 つで、どちらもフォールバックがあります。AVFoundation バックエンドは `hasattr` で守られていて、なければ `CAP_ANY` に落ちる。カメラの自動選択は `system_profiler` に依存していて、なければ番号 0 に落ちる。残りは素の OpenCV / MediaPipe です。`start-live.command` は macOS のダブルクリック用なので、ほかの環境では `run.sh` か `python main.py` を。動いたら issue で教えてもらえると助かります。
