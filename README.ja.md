# manual-tracking

Python だけで動くリアルタイムの手のエフェクトです。MediaPipe の手トラッキングと OpenCV で、**折り紙ミラー・ガラスの箱・浮遊キューブ・TouchDesigner 風バナー・ネオンのワイヤー骨格**の 5 種類を自分の手に貼り付けます。Mac 一台と内蔵カメラだけ、GPU は不要。1080p で 30 fps を切りません。

![5 つのスタイル](docs/img/styles.jpg)

（合成した手と生成した背景で描いたイメージ図です。実機だと自分の手にエフェクトが乗るので、これよりだいぶ見栄えがします。）

## はじめかた

```bash
git clone https://github.com/Eureka0w0v0/manual-tracking.git
cd manual-tracking
./run.sh                 # venv 作成 → 依存インストール → モデル取得(7.5 MB, sha256 検証) → 浮遊キューブで起動
```

macOS がカメラの許可を聞いてくるので「OK」を押します。あとはカメラの前に手を出すだけ。`S` でスタイル切り替え、`Q` で終了。
`start-live.command` をダブルクリックしても同じです（先に許可ダイアログを出してくれます）。

動作環境は macOS（実機で確認済み）と Python 3.12〜3.14。Linux / Windows は未確認ですが、コードにはフォールバックがあります（チュートリアル末尾を参照）。

**チュートリアル全文**（インストール、各ジェスチャーのやり方、リアルタイム調整、録画、オフライン描画、トラブルシューティング、アーキテクチャ）→ [`docs/TUTORIAL.ja.md`](docs/TUTORIAL.ja.md)

コード内のコメントと詳細ドキュメント 2 本（`docs/GLASS_BOX_GEOMETRY.md`、`docs/TOUCHDESIGNER_SETUP.md`）は中国語です。それぞれ冒頭に日本語の要約を付けてあります。

## 5 つのスタイル

`S` キーでこの順に切り替わります。`--style` で直接指定も可能。旧名（`fabric`/`frame`/`planes`/`fluid` → mirror、`track` → screen、`outline` → wire）もそのまま使えます。

- **`mirror` 折り紙ミラー**。両手の親指と人差し指の先に四隅を固定した一枚の紙。平らに持てば反転ミラー（`clamp(283 − 0.56 × 背景)`）、片手を返すとその半分が暗くなって折れ、両手をずらすとねじれ、両手ともつまみ切ると細い二重線になります。
- **`screen` ガラスの箱**。両手で支える**パラメトリックな剛体の直方体**です。手は頂点を固定せず、ノイズの少ないパラメータを数個渡すだけ（手ごとに、手のひら中心と指先の弧の中点の間を補間したアンカー → 長軸と長さ、指先の広がり → 高さ、両手の手のひら幅の比 → 長軸の奥行き成分、手のひらの向き → 長軸まわりの回転）。直方体は 3D で組み立ててから弱透視投影するので、剛性と二点透視は「後から補正」ではなく「構造として」出ます。面の可視判定は 3D の外向き法線と Lambert 照明。**両手を近づけると箱がつぶれて消え、離すとまた伸びてきます。** 6 面それぞれ違うピクセル処理：

  | 面 | 処理 | 出どころ |
  |---|---|---|
  | 上 | 青の反転グラデーションマップ + 横縞グリッチ | 元動画をピクセル単位で実測 |
  | 前 | リソグラフ風 2 色刷り（版ずれの縁 + ディザ） | TD 画面録画の再現 |
  | 後 | ハードしきい値の 2 色（シルクスクリーン / ポラロイド） | TD 画面録画の再現 |
  | 底 | 点群 / ホログラム（単眼近似、局所コントラストを疑似深度に） | TD 画面録画の再現 |
  | 左端 | 四分木の適応モザイク | TD 画面録画の再現 |
  | 右端 | ハーフトーン（温かみのある紙 + インク） | オリジナル |

  各定数を元動画からどう逆算したか、試して捨てた案は何か、は [`docs/GLASS_BOX_GEOMETRY.md`](docs/GLASS_BOX_GEOMETRY.md)（中国語、冒頭に日本語要約）。

- **`cube` 浮遊キューブ**。`screen` との根本的な違いは**自分の姿勢を持っていること**。位置・向き・大きさをキューブ自身が持ち、手はただのコントローラーです。手を離せばその場に残って、ゆっくり自転し続けます（約 10°/秒）。6 面は上の 6 種類の処理をそのまま使います。

  | 手の動き | 結果 |
  |---|---|
  | 片手で**キューブの上でつまんで**ドラッグ | 回転。横に引けば縦軸まわり、縦に引けば横軸まわり。つかんだ瞬間、つまんだ点から**波紋**が広がります（つかめた合図）。空中でつまんでも何も起きません。つかむ = つまむ ∧ つまんだ点がキューブ上。一度つかめばどこへ引いてもついてきて、検出が 0.25 秒ほど途切れても外れず、1 フレームだけの「離した」スパイクも無視 |
  | 両手とも**キューブの上でつまむ** | 移動（両手の中点に追従）+ 拡大縮小（両手の距離に追従）+ **ひねり**（ハンドルを回すように両手を回す → 画面法線まわりの回転。ドラッグでは届かない第 3 軸） |
  | **五本指を開く** | **分解表示**。6 面がそれぞれの法線方向へ飛び出して浮かびます。6 種類の処理を一度に見られる唯一の姿勢。握るか手を下ろせば元に戻る |
  | 手を離す | 運動量を持ったまま。回転は滑り続け、移動は流れ続け、**画面の端で跳ね返り**、摩擦で止まってから自転に戻ります。`F` で重力を入れると、離した瞬間から**放物線**を描いて落ち、床で跳ねて転がって止まる |

  回転は手のひらの向きではなく**ドラッグの差分**で駆動しているので、同じ方向に引き続ければ無限に回ります。`screen` のように途中で戻ってくることはありません（`screen` は手のひら向き信号の cos 型飽和に縛られています。`docs/GLASS_BOX_GEOMETRY.md` §6）。操作感は `tools/cube_check.py` の自動アサーションで固定しています。

- **`banner` TouchDesigner 風バナー**。黄色のしきい値ヘッドバンド / X 線風の中央窓 / 白い区切り線 / 親指の下にはみ出す赤いフットバンド。全部カメラ映像の画面空間 2 色化です。
- **`wire` ネオンのワイヤー骨格**。グロー + 芯線 + 骨に沿って流れる光点。ジェスチャー不要、一番軽いスタイル。

## キー操作

| キー | 動作 |
|---|---|
| `S` | mirror / screen / cube / banner / wire |
| `D` | カメラ背景 / 黒背景 |
| `o` `p` | 背景の明るさ（暗く / 明るく） |
| `R` | 録画（実測フレームレート、HUD なし）→ `output/live_*.mp4` |
| `Q` / `Esc` | 終了 |

`screen` のリアルタイム調整（現在値は HUD に出ます）：

| キー | パラメータ | 効果 |
|---|---|---|
| `[` `]` | `roll_expo` | 反転カーブの急さ（小 = 敏感、大 = 中央が鈍く静止時は安定） |
| `;` `'` | `anchor_lift` | 箱をぶら下げる高さ（0 = 手のひら中心、1 = 指先の弧の中点） |
| `,` `.` | `depth_bias` | 長軸まわり回転の不動点（0 = 前面、0.5 = 中心、1 = 背面） |
| `7` `8` | `roll_max_rate` | 角速度の上限 °/フレーム（手のひら向き信号が飽和域で符号反転したときの瞬間移動を止める。色のちらつきを抑える主役） |
| `9` `0` | `roll_resp` | 回転の追従度（大 = 手についてくる、小 = なめらか） |
| `-` `=`（または `_` `+`） | `anchor_resp` | アンカーの追従度（大 = 追従、小 = 安定だが鈍い） |
| `<` `>` | `gap_shut` | 両手をどこまで近づけたら箱をしまうか（手のひら幅で正規化、カメラとの距離に依存しない） |
| `{` `}` | `box_edge_w` | 稜線の太さ px（0 = 継ぎ目なし、デフォルト 0） |

`cube` のリアルタイム調整：

| キー | パラメータ | 効果 |
|---|---|---|
| `9` `0` | `orbit_gain` | 1 px のドラッグで何度回るか（大 = ちょっと動かすだけで一回転） |
| `g` `h` | `face_alpha` | ガラスの透け具合 |
| `{` `}` | `box_edge_w` | 稜線の太さ |
| `F` | `gravity` | 重力オン / オフ |
| `X` | — | 姿勢リセット（ぐちゃぐちゃになった、端に押し込んだとき） |

3 つの表は**スタイルごとに分かれています**。今のスタイルで使えないキーを押すと、ターミナルに `[ 只对 screen 有用 (当前 cube)`（「screen 専用（今は cube）」）と一言出て、画面に影響しない値を黙って書き換えることはしません。起動時のバナーとこのメッセージは同じキー表から生成していて、手書きコピーはありません。

HUD の末尾には今カメラを向いている面（例 `顶+前` = 上+前）が出ます。回転を調整するとき「幾何が回っていない」のか「回ったが読めない」のかを見分けるためのものです。

## コマンドライン

```bash
./run.sh live                              # デフォルトは cube、1920x1080、内蔵カメラを自動選択
./run.sh live --style screen               # 最初からガラスの箱
./run.sh live --fps 60                     # 60 fps でキャプチャ要求（カメラ次第。検出は 6.9 ms なので追いつきます）
./run.sh live --window-scale 1.4           # ウィンドウを大きめに（角をドラッグしても可）
./run.sh run  -i in.mp4 -o out.mp4 --style screen   # 動画をオフラインで描画
./run.sh dump -i in.mp4 -o landmarks.json           # フレームごとの 21 点を JSON に書き出し（After Effects / TD 用）
python main.py live --style mirror         # IDE 向けの入口、引数は同じ
```

全オプションと JSON の形式は [`docs/TUTORIAL.ja.md` §6](docs/TUTORIAL.ja.md#6-コマンドライン完全リファレンス)。

`src/manual_tracking/__main__.py` を**直接実行しないでください**。相対 import を使っているので `python -m manual_tracking` 経由でしか動きません。`main.py` は IDE でその制約を回避するためだけに存在します。パッケージはあえて pip install しない設計で、`run.sh` / `main.py` / `.vscode` が `PYTHONPATH=src` を設定してくれます。

初回起動時に MediaPipe の手モデルを `models/` へ自動ダウンロードします（公式のバージョン付き URL、内容は不変、sha256 で検証）。自前のモデルを使うなら `--model /path/to/xxx.task`（明示指定したときは**自動ダウンロードしません**）。

## どこを変えればいいか

調整できる定数は、担当モジュールの先頭にまとめてあり、どれも「なぜこの数値か」が一行添えてあります。リアルタイムのキーが変えるのは同名のフィールドで、終了すればデフォルトに戻ります。

| 変えたいもの | ファイル |
|---|---|
| 各面のピクセル処理（リソ / 2 色 / 点群 / 四分木 / ハーフトーン / 上面グリッチ） | `effects.py` |
| `screen` の箱の幾何とフィルタ | `glassbox.py` |
| `cube` の操作感（ゲイン、慣性、重力、分解、つかみ判定） | `floatcube.py` |
| `mirror` / `banner` / `wire` の 3 スタイル | `sheet.py` / `banner.py` / `neon.py` |
| 直方体の頂点順と弱透視投影（`screen` と `cube` が共有する**唯一**のコピー） | `boxgeom.py` |
| 多角形の塗りと線の描画プリミティブ | `paint.py` |
| 手のフィルタ（One Euro、トラック、利き手のラッチ） | `tracker.py` |
| 検出スレッドと速度外挿 | `detect_service.py` |
| キー操作、録画、HUD、メインループ | `live.py` |

`renderer.py` に残っているのは「スタイル別の振り分け + `screen`/`cube` の描画 + 背景キャッシュ + 左右役割のヒステリシス」だけ。アーキテクチャの案内は [`docs/TUTORIAL.ja.md` §8](docs/TUTORIAL.ja.md#8-どう動いているかアーキテクチャ案内)。

## 開発

```bash
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/ruff check main.py src tools tests                # 静的チェック（設定は pyproject.toml）
.venv/bin/pytest                                           # 純ロジックのテスト + 描画スモーク、163 件、1 秒未満
PYTHONPATH=src .venv/bin/python tools/cube_check.py        # cube 操作感のボトムライン、27 アサーション
PYTHONPATH=src .venv/bin/python tools/e2e_check.py         # screen 操作感のボトムライン、3 アサーション（サンプル動画が必要、下記）
PYTHONPATH=src .venv/bin/python tools/e2e_check.py --sweep # expo/cap をスイープしてパラメータ探し
```

チェックは 3 段階で、それぞれ別の壊れ方を受け止めます：

| 段階 | 場所 | 何を止めるか | 必要なもの |
|---|---|---|---|
| テスト | `tests/` | 「変更を間違えて落ちる」: 面トポロジと頂点順の整合、エフェクトのサイズ / 不変契約、箱の剛性、別名表、利き手ヒステリシス、外挿と録画フレームレート、キーのスタイル分け、入口のデフォルト、モデル DL の検証、終了時の後片付け | なし（合成の手、素材不要） |
| 操作感 | `tools/cube_check.py` | 引けない、戻ってくる、離すとふらつく、画面外にはみ出す | なし（合成の手） |
| 回帰 | `tools/e2e_check.py` | 「変更で悪くなった」: 色のちらつき、背面が読めない | サンプル動画 + モデル |

前の 2 段階はカメラも素材もモデルも触らないので、push のたびに CI で回ります（`.github/workflows/ci.yml`）。**3 段階目はローカル専用**。CI が緑でもちらつきがないとは限りません。`screen` の幾何 / 写像 / フィルタを触ったら必ず `e2e_check` を回してください。「可視面が毎秒 5 回切り替わる」ような体感の事故を拾えるのはこれだけです。

`assets/sample.mp4` は**リポジトリに入っていません**（元の作者の動画なので、勝手に配れません）。3 段階目を回すには、両手を返す 1080p/30fps の動画を自分で撮ってそのパスに置いてください。`docs/` の数値はすべて元動画で測ったものなので、自分の素材に替えたら `docs/GLASS_BOX_GEOMETRY.md` §3.7 のやり方で `--sweep` を回してベースラインを取り直す必要があります。

`tools/synth.py` は `tests/` と `cube_check` が共用する合成の手です。
